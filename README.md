# blorp

A terminal UI for triaging a Fastmail account's mailboxes over JMAP. Rust, ratatui.

Status: in development. `blorp` shows the Inbox: `j`, `k`, `g`, `G`, and count prefixes move the cursor, `e` archives the selection, `z` snoozes it, `.` repeats the last action, `u` undoes the last action and `Ctrl-r` redoes it, and `q` quits. `/` opens the filter prompt, which narrows the queue as you type: `in:<mailbox>` (or `in:any`), `from:`, `to:`, `subject:`, `is:unread`, `is:read`, `is:flagged`, `is:list`, `has:attachment`, and bare text, each negated by a leading `-`, with double quotes around values that hold spaces. Enter keeps the filter, Esc puts the earlier queue back, and Up and Down walk this session's filters. `t` toggles newest and oldest first. `:` opens the command line, which runs `:archive` (`:e`), `:snooze <time>` (`:z`), `:unsnooze` (`:uz`), `:undo [count]` (`:u`), `:redo`, `:filter [text]`, `:sort [newest|oldest]`, `:refresh`, `:dry [off]`, and `:quit` (`:q`) on the same selection as a key, with a count typed before the colon (`3:archive`). Tab and Shift-Tab complete command names, filter tokens, `in:` mailbox paths, `:sort` values, and `:snooze` presets and weekdays, and Up and Down walk this session's commands. The selection is the visual range opened with `V` and extended with `j` and `k`, else the rows marked with `x` (`X` clears the marks), else the thread under the cursor, or as many threads from it as a count gives (`3e`). `blorp --dry-run`, or `D` while running, turns on dry run: actions change the queue on screen and are written to the log at `~/.local/state/blorp/blorp.log` instead of being sent to Fastmail.

`z` opens the snooze picker: `l` later today (three hours on, rounded up to the hour, or tomorrow morning after 20:00), `t` tomorrow at 08:00, `w` Saturday at 08:00, and `n` Monday at 08:00, in the local time zone; `j`, `k`, and Enter choose one too, and Esc closes it. `:snooze` takes the preset names `later`, `tomorrow`, `weekend`, and `next`, a duration (`30m`, `2h`, `3d`, `1w`), a clock time (`17:30`), a weekday (`mon`, or `mon 9`), or a date (`2026-11-02`, or `2026-11-02 14:30`). A snooze moves the thread's messages in the queue mailbox to a `Snoozed (blorp)` mailbox, which blorp creates on the first snooze, and records where each came from in `~/.local/state/blorp/snooze.json` (or under `$XDG_STATE_HOME`). At launch, on every reconcile, and on `R`, each thread whose time has come goes back where it came from, marked unread, and sorts by when it returned. A thread also returns early when it gains an email received after it was snoozed in any mailbox other than the snooze mailbox, Trash, Junk, Drafts, and Sent, and a thread found in the snooze mailbox with no schedule entry returns to the Inbox. `in:"Snoozed (blorp)"` shows the snoozed threads with the time until each returns, soonest first (`t` toggles to latest first); there `z` reschedules, `:unsnooze` returns the selection now, and `e` archives it and drops its schedule entry.

The queue follows changes made elsewhere, such as in the web client: blorp listens on Fastmail's push stream and re-runs the queue's query on each change, once a minute, and on `R` or `:refresh`. In dry run the push stream and the minute tick are ignored, and `R` resets the queue to Fastmail's and clears the undo history.

blorp needs a Fastmail API token with the Email scope only (not read-only, and not Email submission), created in Fastmail under Settings, Privacy & Security, Connected apps & API tokens. On the first launch blorp asks for one, checks it with Fastmail, and stores it in the macOS login keychain (service `blorp`, account `fastmail`). `blorp setup` replaces the stored token and `blorp logout` deletes it; neither revokes the token, which is done in Fastmail Settings. `BLORP_API_TOKEN`, when set, is used in place of the keychain, for CI and scripted runs. A rebuilt development binary asks once for keychain access; that is expected.

The log is `~/.local/state/blorp/blorp.log` (or under `$XDG_STATE_HOME`), filtered by `BLORP_LOG` in `RUST_LOG` syntax.

`cargo test` needs no network beyond localhost and no secrets. The end-to-end tests run the binary in a pseudo-terminal against a local JMAP server, through two variables that only debug builds read: `BLORP_SESSION_URL` replaces Fastmail's session URL, and `BLORP_TOKEN_STORE=<path>` replaces the keychain with a file. `cargo test --test live -- --ignored` runs read-only smoke tests against Fastmail with `BLORP_API_TOKEN` set, one of them the end-to-end harness in a pseudo-terminal. `cargo test --test keychain -- --ignored` checks the keychain adapter against the real login keychain under a throwaway service name; it needs no token.
