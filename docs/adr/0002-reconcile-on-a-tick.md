# Reconcile on a fixed tick, not change polling

While connected, blorp reconciles every 60 s whether or not the push stream is up, and also on every push event and on `R`. While disconnected, the same timer runs the probe backoff instead. `update` owns that one timer through `App`'s `next_reconcile_at`, and the `sync` task only runs the EventSource stream. The rejected alternative polled `Email/changes` and `Mailbox/changes` only while the stream was down, with the timer in `sync`. That poll saved little, since a reconcile re-runs the query anyway. Splitting the timer between `sync` and `update` let the poll tick and the probe backoff reset each other, and on a healthy stream a due snooze returned only when something unrelated changed on the server. The tick bounds snooze return to a minute and costs one query request a minute while idle, far below Fastmail's limits.
