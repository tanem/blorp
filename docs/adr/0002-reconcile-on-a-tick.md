# Reconcile on a fixed tick, not change polling

While connected, blorp reconciles every 60 s whether or not the push stream is up, and also on every push event. While disconnected, the same timer runs the probe backoff instead. `update` owns that one timer through `App`'s `next_reconcile_at`, and the `sync` task only runs the EventSource stream. The rejected alternative polled `Email/changes` and `Mailbox/changes` only while the stream was down, with the timer in `sync`. That poll saved little, since a reconcile re-runs the query anyway. Splitting the timer between `sync` and `update` let the poll tick and the probe backoff reset each other. The tick costs one query a minute while idle, sent as a request for the threads and, unless the queue is empty, one or more for their emails, far below Fastmail's limits.
